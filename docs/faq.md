# 常见问题与局限

## 这是一个能用于生产的语音识别系统吗？

不是。voxlink 是一个**参考 / 教学**实现，重点在于把「语音接入语言模型」的结构
讲清楚，并保证可离线复现。它默认使用玩具级别的合成语音和 n-gram 语言模型，识别
性能不代表真实系统。

## 为什么不直接用 numpy / PyTorch？

核心内核刻意保持**纯 Python、零强制依赖**，这样：

- 任何有 Python 的环境都能开箱即用，无需编译或下载大依赖；
- 每个算法（FFT、k-means、n-gram、beam search）都是可读的参考实现；
- CI 能在几秒内端到端跑通。

需要时可以 `pip install 'voxlink[numpy]'` 打开加速后端；接口与数值结果一致。

## 能接入真正的大语言模型吗？

可以。`LanguageModel` 是一个协议，只要实现 `vocab_size` 与 `logprobs(prefix)`，
就能替换掉内置的 n-gram 模型并复用解码器与管线。同理，`SpeechEncoder` 协议允许
替换语音编码器。

## 结果为什么是确定性的？

所有随机性都通过显式的 `Rng`（xorshift32）注入，不使用全局随机状态。同样的种子
在任何平台、任何 Python 版本上给出同样的序列。

## 已知局限

- 合成语音是正弦叠加，不反映真实声学分布；
- n-gram 语言模型无泛化能力，遇到未见的单元组合会退化；
- 线性重采样未做抗混叠，不适合高保真场景；
- 未处理多说话人、噪声、远场等真实难点。

这些取舍都是**刻意**的——用最小但真实的算法把思想讲透，胜过一个黑箱。
