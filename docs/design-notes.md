# 设计笔记：离散语音单元

这份笔记记录 voxlink 在「如何把语音接进语言模型」上的一些取舍。

## 为什么用离散单元

把语音接入语言模型主要有两条路：

1. **连续表示 + 投影**：把编码器输出的连续帧向量，用一个适配器（如线性投影）
   映射到语言模型的嵌入空间，作为「软 token」拼在文本前面。
2. **离散单元**：先把连续特征用聚类（如 k-means）量化成有限个「语音 token」，
   再像普通文本 token 一样喂给语言模型。

voxlink 两条路都提供了组件（`adapter` 对应第一条，`units` 对应第二条），但**默认
链路走离散单元**，原因是：

- 离散单元让语音和文本落在同一个「词表 + 自回归」的框架里，语言模型的训练与
  解码代码可以完全复用；
- 单元序列是整数，天然可序列化、可读、可版本控制，便于调试与复现；
- 用一个纯 Python 的 n-gram 语言模型就能端到端跑通，无需任何深度学习框架。

## 单元数与去重

- **单元数 `n_units`**：类似「音素表」的大小。太小会把不同发音混在一起，太大会
  让每个单元样本过少、语言模型稀疏。参考实现默认 100，玩具语料上 16~32 就够。
- **游程去重**：相邻的重复单元往往对应同一段稳态发音，去重能显著缩短序列、
  降低语言模型的负担，代价是丢失时长信息。默认开启。

## 语言模型的角色

参考实现是一个带回退的 n-gram 模型。它显然无法与神经语言模型相比，但足以：

- 在小语料上**过拟合**，从而验证「语音 → 单元 → 文本」的链路确实打通；
- 提供一个稳定、确定性的 baseline，让评估与解码代码有东西可测。

`LanguageModel` 是一个协议（`Protocol`）：任何实现了 `vocab_size` 与
`logprobs(prefix)` 的对象都能插进解码器与管线。这为将来接入更强的模型留了口子。

## 已知局限

- 合成语音是玩具级别的正弦叠加，不代表真实声学分布；
- n-gram 语言模型没有泛化能力，遇到训练中未见的单元组合会退化；
- 线性重采样未做抗混叠，不适合高保真场景（见 `dsp.resample` 的 TODO）。

这些局限是**刻意**的——voxlink 的目标是把结构讲清楚，而不是刷指标。
